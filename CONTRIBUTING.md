# Как внести вклад в проект

Спасибо за интерес к подсистеме **«Объектное хранилище»**! Приветствуются сообщения об ошибках,
предложения и merge request.

## Сообщения об ошибках и предложения

Перед созданием issue:

1. Убедитесь, что похожая проблема ещё не заведена в
   [трекере](https://gitlab.com/Vladimirov-Maxim/object-storage/-/issues).
2. Укажите версию платформы 1С:Предприятие, версию БСП, версию Коннектора HTTP и версию
   конфигурации, в которую внедрена подсистема.
3. Приложите шаги воспроизведения, ожидаемое и фактическое поведение, при возможности —
   текст ошибки и данные технологического журнала.

## Внесение изменений (merge request)

1. Сделайте форк репозитория и создайте ветку от `main`:
   ```sh
   git checkout -b feature/краткое-описание
   ```
2. Ведите разработку в **1С:EDT**. Исходники в текстовом формате находятся в `ObjectStorage/src`.
3. Соблюдайте:
   - **префикс `ох_`** для всех новых объектов метаданных;
   - [стандарты разработки 1С](https://its.1c.ru/db/v8std);
   - стиль оформления кода и комментариев, принятый в БСП (описание методов над экспортными
     процедурами/функциями с параметрами и возвращаемыми значениями).
4. Проверьте, что изменения собираются в EDT без ошибок и предупреждений валидации.
5. Обновите [README.md](README.md) и [CHANGELOG.md](CHANGELOG.md), если менялись поведение,
   состав объектов или порядок установки.

## Оформление commit-сообщений

Используйте краткий информативный заголовок в повелительном наклонении, при необходимости —
тело с описанием причины изменения. Например:

```
Добавить повторную обработку ошибок очереди

Ранее задания с временной ошибкой сети не переобрабатывались.
```

## Ветвление

- `main` — стабильная ветка. Прямые push в `main` не приветствуются, изменения вливаются через MR.
- Ветки функциональности: `feature/…`, исправлений: `fix/…`.

## Лицензия вклада

Отправляя merge request, вы соглашаетесь на распространение вашего вклада на условиях
лицензии [MIT](LICENSE).

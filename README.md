# Объектное хранилище (Object Storage)

> Подсистема интеграции конфигураций **1С:Предприятие 8** с S3‑совместимыми объектными
> хранилищами: вынос присоединённых файлов из базы в хранилище, отложенная (асинхронная)
> обработка через очередь заданий, регламентное сопровождение и мониторинг.

## Возможности

- **Вынос файлов в S3.** Присоединённые файлы (подсистема БСП «Работа с файлами») автоматически
  выгружаются в объектное хранилище, а в базе остаётся ссылка на объект в хранилище.
- **S3‑коннектор** (`ох_КоннекторS3`) — загрузка, получение, удаление файлов, генерация
  подписанных ссылок (presigned URL), перечисление бакетов и объектов, определение MIME‑типа.
- **Асинхронная обработка** через очередь заданий и регламентное задание: операции над
  хранилищем не блокируют пользовательские транзакции.
- **Повторная обработка ошибок** с ограничением числа попыток и настраиваемой базовой задержкой
  (backoff) — устойчивость к временной недоступности хранилища.
- **Многопоточность.** Обработка очереди в несколько потоков с настраиваемым числом заданий на поток.
- **Регламентное сопровождение:** очистка выполненных заданий и удаление файлов по сроку хранения.
- **Мониторинг** выполнения заданий отдельным отчётом.
- **Мягкая (подписочная) интеграция:** регистрация файлов работает через подписки на события и
  корректно деградирует, если зависимости (БСП, «Работа с файлами», определяемые типы) не настроены.

## Как это работает

```
Запись/удаление присоединённого файла
        │
        ▼
Подписки на события  ─────►  Регистрация в очереди заданий
(ох_РегистрацияФайлов…)      (РегистрИнформации ох_ОчередьЗаданийОбъектногоХранилища)
                                     │
                                     ▼
                      Регламентное задание «Обработка заданий»
                      (ох_ОбработкаЗаданийОбъектногоХранилища)
                                     │
                          ┌──────────┴──────────┐
                          ▼                      ▼
                  ох_КоннекторS3          Повтор при ошибке
                  (загрузка/удаление/     (backoff, лимит попыток)
                   ссылка)                        │
                          │                       ▼
                          ▼             Мониторинг (отчёт)
                 S3‑совместимое
                 объектное хранилище
```

Отдельное регламентное задание «Регламентные операции» выполняет обслуживание: чистит историю
заданий и удаляет файлы по сроку хранения.

## Требования

Протестировано на следующих версиях:

| Компонент                     | Версия            |
|-------------------------------|-------------------|
| Платформа 1С:Предприятие      | 8.3.24+ (режим совместимости 8.3.24) |
| БСП (Библиотека стандартных подсистем) | 3.1.12.254 |
| Коннектор HTTP                | 2.6.1             |
| 1С:EDT                        | для работы с исходниками проекта |

Конфигурация, в которую внедряется подсистема, должна включать подсистему БСП
**«Работа с файлами»** и настроенные определяемые типы владельцев/файлов — иначе интеграция
переходит в «спящий» режим и файлы не регистрируются.

## Установка

Подсистема поставляется как файл конфигурации/исходники EDT и внедряется в целевую конфигурацию
через сравнение и объединение.

### Через Конфигуратор

1. Откройте целевую конфигурацию в конфигураторе.
2. **Конфигурация → Сравнить, объединить с конфигурацией из файла…** и укажите файл поставки
   подсистемы (`.cf`).
3. В окне объединения снимите галочку с **корня** конфигурации, чтобы не переносить лишние
   свойства и объекты донора.
4. **Действия → Отметить по подсистемам файла…**.
5. Отметьте подсистему **`ох_ОбъектноеХранилище`** и нажмите **Выполнить** — будут отмечены все
   объекты подсистемы.
6. Нажмите **Выполнить → Продолжить**.
7. Конфигуратор попросит **указать источники** для объектов, чьи типы в доноре не заданы явно
   (они реализованы через определяемые типы и подписки — это точки расширения под вашу
   конфигурацию). Заполните их под свой прикладной проект:

   **Подписки на события** — задают, при изменении каких объектов регистрировать файлы:

   | Объект (источник) | Что указать |
   |-------------------|-------------|
   | `ох_РегистрацияФайловОбъектногоХранилищаПриЗаписи` | Объекты, **при записи** которых файлы регистрируются на выгрузку в S3 (справочники присоединённых файлов и/или их владельцы) |
   | `ох_РегистрацияФайловОбъектногоХранилищаПередУдалением` | То же, но регистрация выполняется **перед удалением** объекта (для удаления файла из S3) |
   | `ох_РегистрацияФайловОбъектногоХранилищаПриЗаписиНабораЗаписей` | **Регистры**, при изменении набора записей которых также нужно регистрировать файлы |

   **Определяемые типы** — задают состав данных, которыми подсистема обменивается с хранилищем:

   | Определяемый тип | Что указать |
   |------------------|-------------|
   | `ох_ВладелецПрисоединенныхФайловОбъектногоХранилища` | Владельцы файлов (объекты-хозяева), файлы которых выгружаются в S3 |
   | `ох_ПрисоединенныеФайлыОбъектногоХранилища` | Сами справочники присоединённых файлов, которые выгружаются в S3 |

   Типы источников подписок должны быть согласованы с составом этих определяемых типов.

### Через 1С:EDT

```sh
git clone https://github.com/Vladimirov-Maxim/Object-Storage.git
```

Импортируйте проект `ObjectStorage` в рабочую область 1С:EDT
(**File → Import → 1C:EDT → Existing Projects into Workspace**) и подключите к целевой информационной базе.

## Подключение как библиотеки

Подсистема спроектирована как **встраиваемая библиотека**: все объекты имеют префикс `ох_` и
собраны под единой корневой подсистемой `ох_ОбъектноеХранилище`, а связь с прикладной
конфигурацией вынесена в определяемые типы и подписки (см. [Установка](#установка)). Это
позволяет внедрять её в произвольную конфигурацию без конфликтов имён. Поддерживаются два способа
подключения.

### Классическая поставка (объединение конфигураций)

Основной, совместимый со всеми версиями способ — поставка `.cf` и внедрение через
**«Сравнить, объединить с конфигурацией из файла…»** (см. раздел [Установка](#установка)).
Именно так подключается большинство библиотек экосистемы 1С (в т.ч. БСП).

### Нативный механизм библиотек 1С:EDT

Начиная с **1С:EDT 2025.2** доступен встроенный механизм библиотечной разработки (на момент
написания — бета): библиотека публикуется в локальный репозиторий, а проект-потребитель объявляет
её зависимостью, после чего EDT подмешивает объекты библиотеки при сборке.

Проект уже подготовлен к этому механизму:

- задан **префикс имён** конфигурации (`ох_`);
- заполнены **версия** и **поставщик** (используются при обновлении библиотеки у потребителя);
- точки интеграции реализованы через определяемые типы, а не жёсткие ссылки на объекты хоста.

Порядок работы в EDT:

1. Репозиторий библиотек задаётся в **Окно → Параметры → V8 → Библиотеки → Репозиторий библиотек
   конфигурации**.
2. Опубликуйте проект `ObjectStorage` как библиотеку в этот репозиторий.
3. В проекте-потребителе добавьте библиотеку в зависимости и выполните сборку.
4. Обновление библиотеки у потребителя выполняется штатным сценарием обновления EDT.

> Точные названия команд могут отличаться между версиями EDT; механизм имеет статус бета —
> подробности см. в руководстве разработчика 1С:EDT, раздел «Библиотечная разработка».

## Настройка

После внедрения задайте параметры в константах и справочниках подсистемы:

1. **Справочник «Сервисные аккаунты» (`ох_СервисныеАккаунтыОбъектныхХранилищ`)** — адрес сервера,
   регион, тип аутентификации, идентификатор и секретный ключ доступа к хранилищу. Проверить
   соединение можно методом `ох_КоннекторS3.ПроверитьПодключение`.
2. **Справочник «Бакеты» (`ох_БакетыОбъектныхХранилищ`)** — имена бакетов в хранилище.
3. **Константы** — параметры по умолчанию и режим работы очереди:

   | Константа | Назначение |
   |-----------|-----------|
   | `ох_ИспользоватьИнтеграцию` | Главный переключатель интеграции |
   | `ох_СервисныйАккаунтПоУмолчанию` | Аккаунт по умолчанию |
   | `ох_БакетПоУмолчанию` | Бакет по умолчанию |
   | `ох_МаксимальноеКоличествоПотоковОбработкиЗаданий` | Число потоков обработки очереди |
   | `ох_КоличествоЗаданийВыполняемыхОднимПотоком` | Заданий на поток за один проход |
   | `ох_ОбрабатыватьОшибкиПовторно` | Включить повторную обработку ошибок |
   | `ох_МаксимальноеКоличествоПопытокОбработки` | Лимит попыток |
   | `ох_БазоваяЗадержкаПриПовторнойОбработки` | Базовая задержка (backoff) |
   | `ох_КоличествоДнейХраненияЗаданий` | Срок хранения истории заданий |
   | `ох_КоличествоДнейХраненияФайлов` | Срок хранения файлов |

4. Включите регламентные задания **«Обработка заданий объектного хранилища»** и
   **«Регламентные операции объектного хранилища»**.

Для интерактивной работы и диагностики предусмотрена обработка **«Работа с объектным хранилищем»**
(`ох_РаботаСОбъектнымХранилищем`).

## Регистрация файлов

Какие именно файлы и по каким объектам попадают в очередь на обмен с хранилищем, определяется
справочником **«Настройки регистрации файлов объектного хранилища»**
(`ох_НастройкиРегистрацииФайловОбъектногоХранилища`).

Каждый элемент справочника задаёт:

- **Использовать** — флаг активности настройки;
- **Сервисный аккаунт** и **Бакет** — куда выгружать файлы, попавшие под эту настройку;
- **Объекты регистрации** (табличная часть) — полные имена объектов метаданных, при изменении
  которых срабатывает регистрация;
- **Полное имя функции регистрации** — необязательный произвольный метод обработки (см. ниже).

### Метод регистрации по умолчанию

Если «Полное имя функции регистрации» **не заполнено**, применяется встроенный метод
`ох_РегистрацияФайловОбъектногоХранилища.РегистрацияФайловПоУмолчанию`. Он покрывает типовой
сценарий:

- если зарегистрированный объект — **справочник присоединённых файлов**, регистрируется сам файл;
- если объект — **владелец файлов** (объект, к которому присоединяются файлы), регистрируются все
  его присоединённые файлы;
- операция (**выгрузка** или **удаление**) определяется автоматически по пометке удаления.

Для объектов, которые не являются ни хранилищем файлов, ни владельцем файлов, метод по умолчанию
вызовет исключение — для них нужен произвольный метод.

### Произвольный метод регистрации

Чтобы описать нестандартную логику (например, выгружать файлы по сложному условию или из
собственных структур данных), укажите в «Полном имени функции регистрации» экспортный метод
общего модуля в формате `ИмяМодуля.ИмяФункции`. Метод вызывается с теми же параметрами, что и
метод по умолчанию:

```bsl
// Параметры:
//   Источник    - объект, вызвавший регистрацию (данные записываемого/удаляемого объекта).
//   ЭтоУдаление - Булево - Истина, если регистрация выполняется перед удалением объекта.
//
// Возвращаемое значение:
//   ТаблицаЗначений с колонками:
//     * Файл     - ссылка на присоединённый файл (тип из ох_ПрисоединенныеФайлыОбъектногоХранилища);
//     * Владелец - владелец файла (тип из ох_ВладелецПрисоединенныхФайловОбъектногоХранилища);
//     * Операция - Строка - "Выгрузка" либо "Удаление".
//
Функция МояРегистрацияФайлов(Источник, ЭтоУдаление = Ложь) Экспорт
    ДанныеРегистрации =
        ох_РегистрацияФайловОбъектногоХранилища.НовыйДанныеРегистрации();

    // ...собственная логика отбора файлов...

    Возврат ДанныеРегистрации;
КонецФункции
```

Публичная функция `НовыйДанныеРегистрации` создаёт таблицу требуемой структуры и позволяет не
дублировать её описание в произвольных обработчиках.

Каждая строка возвращённой таблицы ставится в очередь заданий на соответствующую операцию.
Пустая таблица означает «регистрировать нечего».

## Использование

Основной программный интерфейс — общий модуль **`ох_ОбъектноеХранилище`**.

```bsl
// Загрузка файла в объектное хранилище
ПараметрыРаботы = ох_ОбъектноеХранилище.НовыйПараметрыРаботыСОбъектнымХранилищем();
// ...заполнить сервисный аккаунт и бакет...

ПараметрыЗагрузки = ох_ОбъектноеХранилище.НовыйПараметрыЗагрузкиФайла();
ПараметрыЗагрузки.ДанныеФайла.ДвоичныеДанныеФайла = ДвоичныеДанные;

Результат = ох_ОбъектноеХранилище.ЗагрузитьФайл(ПараметрыРаботы, ПараметрыЗагрузки);

// Получение подписанной ссылки на файл
ПараметрыСсылки = ох_ОбъектноеХранилище.НовыйПараметрыПолученияСсылки();
ДанныеСсылки = ох_ОбъектноеХранилище.ПолучитьСсылкуФайла(ПараметрыРаботы, ПараметрыСсылки);

// Удаление файла
ПараметрыУдаления = ох_ОбъектноеХранилище.НовыйПараметрыУдаленияФайла();
ох_ОбъектноеХранилище.УдалитьФайл(ПараметрыРаботы, ПараметрыУдаления);
```

Низкоуровневые операции над хранилищем доступны в модуле **`ох_КоннекторS3`**:
`ПроверитьПодключение`, `ЗагрузитьФайл`, `ПолучитьФайл`, `УдалитьФайл`, `ПолучитьСсылку`,
`ВсеБакетыХранилища`, `ПолучитьФайлыБакета`, `MIMEТипДляРасширенияФайла`.

## Переопределение HTTP-коннектора

По умолчанию подсистема использует общий модуль `КоннекторHTTP`. Если в целевой
конфигурации он имеет другое имя, задайте его в переопределяемом модуле
`ох_ОбъектноеХранилищеПереопределяемый`:

```bsl
Процедура ПриОпределенииИмениМодуляКоннектораHTTP(ИмяМодуляКоннектораHTTP) Экспорт
	ИмяМодуляКоннектораHTTP = "МойКоннекторHTTP";
КонецПроцедуры
```

Модуль должен предоставлять тот же программный интерфейс: `СоздатьСессию`, `НовыеПараметры`,
`ВызватьМетод` и `HMAC`.

## Соглашения о префиксах

Все объекты подсистемы имеют префикс **`ох_`** (от «объектное хранилище»), что исключает
конфликты имён при внедрении в произвольную конфигурацию.

## Разработка

Проект ведётся в **1С:EDT**; исходники хранятся в текстовом формате в каталоге
[`ObjectStorage/src`](ObjectStorage/src). Рекомендуется соблюдать
[стандарты разработки 1С](https://its.1c.ru/db/v8std) и стиль оформления БСП.

## Совместимость

Режим совместимости конфигурации — **8.3.24**, что позволяет внедрять подсистему в конфигурации,
работающие на платформе 8.3.24 и новее. Хранилище должно поддерживать S3‑совместимый протокол
(проверялось на типовых S3‑совместимых сервисах). Для сетевого взаимодействия используется
библиотека **Коннектор HTTP 2.6.1**.
